# Сборка и упаковка

[English](BUILDING.md)

Эта инструкция предназначена для разработчиков, которые собирают DLL или готовят установочный ZIP. Игрокам предназначено [руководство игрока](PLAY.ru.md).

Обычный путь: дважды щёлкните **`Release.cmd`**. Он собирает мод, запускает тесты, обновляет версию и создаёт установочный ZIP. Настройка, проверка через Gale и загрузка описаны в [полной инструкции выпуска](RELEASE.ru.md). Ниже приведены отдельные операции для разработчиков.

Для автоматической публикации используется **GitHub Actions → Release** с выбором patch/minor/major. **`PublishGitHub.cmd`** запускает то же облачное задание. Источники зависимостей, условия и ограничения описаны в инструкции выпуска.

## Соберите DLL

1. Установите PowerShell 7 и .NET SDK 10.
2. Установите Valheim и BepInExPack Valheim 5.4.2351.
3. Откройте PowerShell 7 в папке репозитория.
4. Введите пути к зависимостям при запросе. `GameManaged` означает папку `valheim_Data/Managed` игры. `BepInExCore` означает папку `BepInEx/core` совместимой установки.

```powershell
$gameManaged = Read-Host 'Папка Managed игры Valheim'
$bepInExCore = Read-Host 'Папка core BepInEx'
./build.ps1 -GameManaged $gameManaged -BepInExCore $bepInExCore -OutputDirectory './outputs/local' -DllOnly
```

Результат находится в `outputs/local/ValheimBoombox.dll`. Компилятор читает библиотеки зависимостей и встраивает ресурсы из `assets/`. Игра не запускается, DLL не устанавливается. Храните пути к зависимостям в своей оболочке, вне коммитов.

Параметр `-Compiler` выбирает Roslyn `csc.dll`. Без него скрипт выбирает установленный SDK. Без `-DllOnly` рядом с DLL копируются README и переводы.

## Форматирование C#

Команда `./format.ps1` форматирует исходники и тесты C#. Команда `./format.ps1 -Check` проверяет их без редактирования. Обе используют Roslyn из установленного .NET SDK 10, разворачивают сжатые блоки, разделяют инструкции и переносят длинные списки аргументов и выражения.

Запускайте эти команды локально по необходимости. Они не запускают Valheim и не обращаются к игровым профилям.

## Запустите офлайн-тесты

Используйте те же переменные оболочки и собранную DLL.

```powershell
./test.ps1 -GameManaged $gameManaged -BepInExCore $bepInExCore -ProductDll './outputs/local/ValheimBoombox.dll' -OutputDirectory './outputs/tests'
```

Команда записывает временные данные и `results.json` в `outputs/tests`. При ошибке код завершения ненулевой. Valheim не запускается. Область и ограничения тестов описаны в [руководстве участника](CONTRIBUTING.ru.md).

## Подготовьте установочный ZIP

Для воспроизведения файлов нужны отдельные программы FFmpeg и ffprobe. Подготовьте полный дистрибутив с `bin/ffmpeg.exe`, `bin/ffprobe.exe`, `manifest.json`, `LICENSE`, `README.txt` и `Sources/`. В папке исходников должны находиться соответствующий исходный архив и материалы пересборки. Используйте [инструкцию FFmpeg](third_party/ffmpeg/README.md).

Для распространения используйте `Release.cmd`. Он передаёт в `package.ps1` собранную DLL с результатом её офлайн-тестов и создаёт `BUILD-INFO.json`. В установочный ZIP входят плагин, переводы, программы обработки звука, лицензии, манифест, иконка, список изменений и английский `README.md`. README ссылается на русское описание и оба руководства игрока в GitHub.

Скриншоты и полные руководства остаются в репозитории исходников. В установочный ZIP они не копируются. Исходный README использует относительные пути картинок, которые GitHub разрешает для читателей с доступом к репозиторию. Упаковка заменяет только эти пути на адреса `raw.githubusercontent.com` для Thunderstore. Перед публикацией пакета с этими картинками репозиторий должен быть публичным, а файлы должны находиться в ветке `main`.

`package.ps1` является внутренней командой упаковки. `Stage` требует явные `SourceDll`, `IconPath`, `FFmpegRoot` и `TestReport` от `test.ps1`; `MetadataDirectory` позволяет передать метаданные кандидатного выпуска. `Archive` получает подготовленный `Destination`. Обе операции пишут только внутри `outputs/`. Существующие папки сохраняются и не перезаписываются. Обычная команда выпуска выбирает рабочую папку и управляет версией сама.

Проверяются манифест, иконка 256×256, хеши файлов и ограничение размера. Упаковка ничего не загружает и не подтверждает приёмку в игре. Следуйте [полной процедуре выпуска](RELEASE.ru.md).

## Обновите переводы или ресурсы

Правьте `Translations/*.json` напрямую. `Translations/catalog.json` задаёт основной запасной словарь. После добавления ключа в него запустите `./check-translations.ps1 -Sync`: команда добавит отсутствующие ключи в остальные языки как `null` и проверит все словари. Существующие переводы сохраняются. Замените каждый `null` переводом и повторяйте ту же команду до успешного результата. Пропуски и незаполненные переводы завершают команду ошибкой с именем файла и ключа. Без `-Sync` команда только проверяет; сборка использует этот режим и останавливается при ошибках перевода. Добавление языков, локальные подмены и настройка культуры описаны в [инструкции перевода](CONTRIBUTING.ru.md#добавить-перевод). Сборка встраивает все JSON переводов, поэтому DLL содержит запасные строки при отсутствии внешних словарей.

Готовые Unity-пакеты в `assets/` используются при сборке. Редактируемые проекты Blender и Unity не включены. При распространении ресурсов сохраняйте [сведения об их происхождении](ASSET-CREDITS.ru.md) и отдельные лицензии сторонних компонентов.
